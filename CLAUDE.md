# Cartographyr

Persistent geographic foundation mod for a modular Minecraft project (Minecraft Java Edition). Part of a suite of intercommunicating mods that expose public APIs so other mods — the user's own and third parties' — can integrate.

## Context directory — read this first

`context/` is a **separate private repo** (https://github.com/CerealKlla/cartographyr-context), not part of this one — it's listed in `.gitignore` here and must never be committed to this repo. It's cloned as a subdirectory at `context/` for local convenience. If this directory is missing (e.g. a fresh clone of just this repo), restore it with:

```
git clone https://github.com/CerealKlla/cartographyr-context.git context
```

Before searching source for architecture, ownership boundaries, API shape, or "why does this work this way," check `context/` first. It's maintained specifically to answer those questions cheaply:

- `context/design-document.md` — the authoritative design spec: architecture, entity model, full public API surface, storage design, implementation phases, testing strategy. Start here for anything about intended shape or scope.
- `context/decisions.md` — dated log of decisions made during implementation that extend or override the design document, with rationale. Check this for anything that looks like it contradicts design-document.md — the doc should already reflect the current decision, but this explains why.
- `context/classes/` — one short markdown file per implemented class: public surface, key state, collaborators. Read the relevant file here before opening the actual source, and before editing a class update its file to match.

**Keep this system current as you work:**
- When a design decision is made that conflicts with or is absent from design-document.md, update design-document.md directly and add a dated entry to decisions.md explaining the change.
- When a class is added or its public surface changes, add or update its file in `context/classes/`.
- Don't let source and these docs drift — treat updating them as part of finishing the change, not optional cleanup.
- `context/` has its own git history, independent of this repo's commits. Commit and push changes there separately (`git -C context add . && git -C context commit -m "..." && git -C context push`) — editing the files alone doesn't back them up.

Phase 1 minimal milestone (design-document.md Appendix B) — implemented 2026-09-23, see [context/decisions.md](context/decisions.md):
- `.geo`/`.storage`/`.api` package split; `EntityId`, `GeographicEntity`, point/bounds `Geometry`, world-level `CartographySavedData`, chunk-grid `SpatialIndex`, and the `Cartography` public facade (create/get/update/retire/getEntitiesAt).
- `EntityType` simplified since: dropped VILLAGE/TOWN/CITY tier and RUIN, collapsed to `REGION, MOUNTAIN, RIVER, SETTLEMENT, MINE, ROAD` — settlement tier isn't Cartography's to classify, and active-vs-abandoned is `LifecycleState`'s job, not a type.
- Structure Association (Section 5.7) — `associateStructure`/`getAssociatedStructures`/`getEntityForStructure` on `Cartography`, backed by vanilla `GlobalPos` and a `structureIndex` reverse lookup on `CartographySavedData`. Completes the PLANNED→REALIZED flow from Section 4.
- Characteristics (Section 5.4) — `addCharacteristic`/`removeCharacteristic`/`getCharacteristics` on `Cartography`, backed by a `Set<Characteristic>` field directly on `GeographicEntity` (no index needed). `Characteristic` is `LUMBER, MINING, FARMING` for now.
- Amenities (Section 5.5) — `addAmenity`/`removeAmenity`/`getAmenities` on `Cartography`, same shape as Characteristics. `Amenity` is `MARKET, MINE, INN, HARBOR` for now.
- Naming (Section 5.3) — `setName`/`addAlternateName`/`getNames` on `Cartography`. New `AlternateName` (name + free-text metadata) and composite `EntityNames` (current + alternate names) types in `.geo`.
- History (Section 5.6) — `addHistoricalFact`/`getHistoricalFacts` on `Cartography`. New `HistoricalFact` (description + `gameTime` + free-text metadata) type; the entity's fact list stays sorted by `gameTime` regardless of insertion order.
- **Section 5's core entity-data endpoints (5.1–5.7) are now complete.**
- Natural Geography (Section 5.8) — new `.natural` package (`NaturalRegionProfile`, `NaturalRegionDiscovery`) flood-fills outward from a point sampling live biome data, discovers/names regions, persists them as a new `Geometry.Region` (irregular chunk-cell shape). `getNaturalRegionAt`/`findNaturalRegions`/`getRegionBounds` added to `Cartography`. **This is the one part of the codebase that can't be unit tested** — needs a live `ServerLevel` to sample biomes; verify manually via `./gradlew runClient`.
- Biome coverage now spans 13 families: `DESERT, FOREST, PLAINS, SWAMP, TAIGA, JUNGLE, SAVANNA, BADLANDS, MOUNTAIN, RIVER, OCEAN, BEACH, NETHER_WASTELAND` (last three added 2026-09-25, see decisions.md — `NETHER_WASTELAND` deliberately covers all five Nether biomes under one shared type/name pool, per explicit user instruction). Still not exhaustive — mushroom fields, cherry groves, ice spikes, cave/End biomes have no profile.
- **Demo entry notification removed entirely, 2026-09-24** (see [context/decisions.md](context/decisions.md)) — it lived here briefly (as a chat message, then a HUD overlay) but was correctly identified as player knowledge/belief, not world truth, so it now lives in Lyfe (`.location` package there) instead. Cartographyr has **no player-facing notification logic of any kind anymore** — it's back to a pure data/query API. Gained `Cartography.discoverNaturalRegion(ServerLevel, BlockPos)` on the public facade to support Lyfe's equivalent tracker (wraps `NaturalRegionDiscovery.discover`, previously internal-only).
- **Section 5.9 (Player Knowledge) permanently removed from scope** (2026-09-24, see [context/decisions.md](context/decisions.md)) — not just deferred. That concept now belongs to the suite's second mod, **Lyfe** (github.com/CerealKlla/lyfe, private context repo lyfe-context), specifically its Historian/Cartographyr skills, which consume Cartographyr's read-only queries rather than Cartographyr owning any player-knowledge API itself.
- `./gradlew build` and `./gradlew test` both green (21 tests total, covering everything except the discovery algorithm itself). Boot-smoke-tested via `./gradlew runServer`.
- **Natural Geography is now considered stable**, confirmed across six playtest iterations while the (since-removed) demo notification exercised it — fragmentation bug found & fixed, verified via temporary diagnostic logging, biome coverage expanded from 2 to 10 families. Diagnostic logging has been stripped back down to just the meaningful state-change logs (a region created/merged) — no more per-tick noise. Full trail in [context/decisions.md](context/decisions.md).
- **`EntityType`/`Classification` migrated from closed Java enums to open, `Identifier`-keyed records, 2026-09-24** (see [context/decisions.md](context/decisions.md)) — this was the real prerequisite the "Next" note below used to point at. Any mod can now construct `new EntityType(Identifier.fromNamespaceAndPath("mymod", "my_type"))` and pass it to `Cartography.createEntity`, no registration step (write governance resolved as **trust-based**, decided with the user this session). Built-in values kept the same names under the `cartographyr` namespace, so nearly every call site was unaffected — the one real change was three `==` comparisons that had to become `.equals()` (records don't intern), all found via a full repo grep and fixed. New test proves a third-party namespace round-trips and compares correctly through the real save/reload codec. **Accepted, undocumented-as-a-bug save-format break**: old persisted values were bare enum names, new ones are `namespace:path` strings — no migration path written, since `run/` is dev-only/gitignored; delete a stale local save rather than treat a decode failure there as a regression.
- **Cartographyr now auto-detects vanilla villages, 2026-09-24** (see [context/decisions.md](context/decisions.md)) — new `Geometry.Polygon` variant (`convexHull` over structure-piece corners, block-precise vertices, not pixel-perfect, falls back to `Bounds` on degenerate/collinear input) plus a new `.settlement` package (`SettlementDiscovery`, `SettlementListener`). Detection is entirely self-triggering — `SettlementListener` hooks `ChunkEvent.Load` (no dedicated "structure generated" event exists in NeoForge; verified against the decompiled source), filters to `StructureTags.VILLAGE` (**v1 scope: villages only**, other structures deferred, same "incremental, not exhaustive" precedent as Natural Geography's biome coverage), and reuses the existing Structure Association API (Section 5.7) for idempotency across repeated chunk loads. This is the world-gen-driven half of Phase 3.5, resolved as **Cartographyr's own responsibility** (unlike player-founded settlements, which stay push-based per the "open N-layer entity model" entry — the split is by what's doing the detecting, not by entity type). A real bug (`List.of` on a partially-filled array threw `NullPointerException`) was caught by the new `GeometryTest` cases before it ever ran live. **This is also the one part of the codebase that can't be unit tested** — same limitation as Natural Geography's own discovery algorithm. **Confirmed live** via `runClient`: the user found a real village, named appropriately, footprint naturally L-shaped and correctly bounded (walking into the void was correctly treated as leaving it).
- **Contextual settlement naming + open Layer registry, 2026-09-24** (see [context/decisions.md](context/decisions.md)) — `SettlementDiscovery` now samples nearby biomes (reusing `natural.NaturalRegionProfile`, widened to `public` for this) and picks a name via new `SettlementNaming`: themed pools per biome family (river, forest, desert, etc.) used only 50% of the time when a feature is found, otherwise an explicitly non-nature-themed neutral pool ("The Town of Dale") — replacing the old flat, context-blind list that happened to name a real river-adjacent village "Brookside" by pure chance. Separately, new open `Layer` (`.geo`, id + label + placement) and `LayerRegistry` (in-memory, trust-based, mirrors `EntityType`/`Classification`'s governance), exposed via `Cartography.registerLayer`/`getLayer`/`getRegisteredLayers` — the first "registry" shaped API in the facade, no `MinecraftServer`/`ServerLevel` param. `GeographicEntity`/`EntityDefinition` gained a `layerId` field (touched every positional constructor site in the codebase, same ripple shape as the `EntityType`/`Classification` migration). Cartographyr's own natural/settlement detection all shares one built-in `Layer.LOCATION_ID` layer at placement 0, registered by `CartographyrMod` at startup. **Cartographyr owns only the registry, not rendering** — Lyfe's `.location` overlay is being updated separately to resolve/sort/render layers (see lyfe-context decisions.md).
- **Compositional word-pool naming, and Designation/SpecialStatus split out of name, 2026-09-25** (see [context/decisions.md](context/decisions.md)) — `GeographicEntity` gained `designation`/`specialStatus` (`Optional<String>`, open/trust-based, intended for `Classification.CONSTRUCTED` entities, **not** a save-format break since both use `optionalFieldOf`), exposed via `Cartography.setDesignation`/`getDesignation`/`setSpecialStatus`/`getSpecialStatus`. `designation` is a settlement's tier ("Village"/"City"/etc., stripped out of `name`); `SettlementDiscovery` now sets a starting value based on structure piece count (`SettlementNaming.designationFor`), with an external town-management mod expected to upgrade it later. `specialStatus` is a separate free-text marker (e.g. "Capital") for a future consumer (a minimap) to treat as notable without interpreting the string itself. Separately, both `natural.NaturalRegionProfile` and `settlement.SettlementNaming`'s naming replaced hand-authored full-phrase/whole-name lists with a new shared `.naming` package (`NameComposer`, `RegionWordPools`) combining small reusable word pools at generation time — far more combinations from the same authored content, and (for settlements) a rewritten `SettlementNamingTest` that verifies the neutral pool can never produce a nature-toned word by checking the pools themselves rather than sampled output.
- **DisplayText moved into Cartographyr; designation order corrected, same day** (see [context/decisions.md](context/decisions.md)) — originally built display-text composition (name+designation+ruin prefix) in Lyfe on a "Cartographyr owns data, not rendering" reading of the Layer-registry precedent; the user pointed out that leaves two mods free to compose the same shared data into different text, exactly the inconsistency putting it in one place was meant to prevent. New `geo.DisplayText#forEntity` (and `Cartography.getDisplayText` facade convenience) is now the one canonical implementation every consumer should call — Lyfe's own copy was deleted and repointed here. The write-side API was checked against the user's four requirements (create-with-name, rename, change size designation, change special designation) and all four were already covered by existing methods; the only real gap was this read-side canonical formatting. Also fixed: `designationFor`'s tier order, which had Village/Outpost and Town/Settlement transposed — correct order is `Hovel < Outpost < Settlement < Village < Town < City`. **Confirmed live the same day** via a ~4-hour `runClient` session, no crashes: real natural-region names showed genuine compositional variety (bare nouns and thematic/size-prefixed ones both appeared), and four real settlement discoveries (64/84/97/171 pieces) all landed on the correct designation tier (Settlement/Village/Village/City respectively), composing correctly end-to-end through the overlay ("Village of Bramton," "City of Corwic," etc.).
- **Generic flavor pool fixed: occasional "of \<word\>" suffix, not a fourth prefix, 2026-09-25** (see [context/decisions.md](context/decisions.md)) — playtest feedback: `RegionWordPools.GENERIC_FLAVOR` had been wired in as a fourth prefix category alongside size/climate/thematic, producing wrong-reading results like "The Sorrow Woods." Fixed so it's applied as a separate, independently-rolled trailing suffix instead (`FLAVOR_SUFFIX_CHANCE = 0.2`) — e.g. "The Ancient Woods of Sorrow," matching the original intent. `./gradlew build`/`test` green; **live confirmation of the new suffix shape is still pending.**
- **`DisplayText.shortForEntity`; `Cartography.findEntities(dimension, Classification)`, 2026-09-25** (see [context/decisions.md](context/decisions.md)) — both driven by Lyfe's first live playtest of its sign/map mechanic. `shortForEntity` composes name+ruin-prefix without the designation, for Lyfe's sign text (the full `forEntity` form was running off a vanilla sign's line width). `findEntities` is a classification-filtered scan (mirrors `findNaturalRegions`'s pattern, but by `Classification` alone) — the first API able to enumerate settlements rather than natural regions or a specific coordinate; Lyfe uses it for a "pick a random known settlement" debug command. `./gradlew build`/`test` green.
- **Cherry grove biome had no profile, same day** (see [context/decisions.md](context/decisions.md)) — another Lyfe-playtest find: standing in a cherry grove produced no natural region at all (no `NaturalRegionProfile` matched it), which Lyfe's `LocationTracker` then compounded into a worse-looking bug (a frozen, stale location overlay — see lyfe-context decisions.md). Fixed by adding `Biomes.CHERRY_GROVE` to the existing `FOREST` profile. `./gradlew build`/`test` green; **live confirmation is still pending.**
- **Full biome-coverage audit, 2026-09-26** (see [context/decisions.md](context/decisions.md)) — after yet another "no location name" playtest report, extracted vanilla's actual `Biomes` class via `javap` and diffed it against `NaturalRegionProfile.ALL` instead of waiting for more one-off reports. Of 65 vanilla biomes, only 6 remain uncovered (`THE_VOID` plus the five End-dimension biomes — no End profile exists). The other 3 gaps found (`SNOWY_PLAINS`, `PALE_GARDEN`, `STONY_SHORE` — all real overworld biomes, previously unnoticed) are now closed. `./gradlew build`/`test` green; live confirmation still pending.
